# t030-ir-renderer — the one offline impulse-response renderer (ROADMAP T-030, M4 batch B4-1)

- **Queue item:** T-030 (D-030; D-029 as amended by D-030). This change also carries the M4 plan (D-030): PR #13 merged
  into `close-m2` after that branch had already reached main, so the plan never landed on main.
- **Why:**
  - D-011 and M4's gate 1 need ONE renderer for the display, the tail oracle and the mono-fold metric.
  - D-030 has M4 build it before M3's T-019 (B3, from 2026-11-09) needs it, so T-019 measures through it.
- **Built:**
  - **`core/include/echo/ir_render.h`:**
    - `IrRenderer` drives a private `Echo` through the public API. It stores every key, Device keys included, then
      resets: the post-load response (D-031).
    - Inputs: impulse (mono, L, R, S-only) or seeded-noise, at a stated level (default −20 dBFS).
    - Stops early at rest and zero-fills.
    - Reports the declared tail and a block-quantised rest point.
    - Refuses a rate the engine would clamp.
    - `irHash`, the cache key, covers every input the render reads.
    - `renderIr` is the one-shot form for tools.
  - **`core/tests/ir_tests.cpp`** builds as `echo_ir_tests` / `echo_ir_plants`: 7 checks and 9 M4 plants (plus the
    engine's `noTailGate`), with plant coverage cross-checked.
  - **Wiring:** `./verify`'s core gate runs both binaries (approved by D-030); CI's sanitizer step runs `echo_ir_tests`.
- **The reference:** `plain()`, an `Echo` that LOADED the patch (`loadState`, plus `setParam` for the Device keys), run
  in 333-sample blocks. It reaches the renderer's state by another route, so the two cannot share a fault.
- **Evidence consulted:**

- **Independent review:** an Opus critic subagent (fresh context, read-only) returned FIX-THEN-SHIP. All findings are
  fixed or recorded, and every fix is guarded by a plant:
  - **H1, the drawing depended on render history:** after a reset, a changed seed blended from the current stream.
    The first reference shared that path. Fixed: values first, then `reset()`. The reference is now the load path
    (D-031). Plant `irSeedAfterReset` fires at sample 7460 in both checks.
  - **M1, restAt missed a rest inside the last block:** fixed. Plant `irRestAtMissesEnd`.
  - **M2, `render()` cannot resume for head-first frames:** recorded as T-031 criterion 6, a resumable form.
  - **M3, gaps:**
    - noise seed and length in the hash (now checked);
    - a 4 kHz request rendered at 8 kHz under a 4 kHz hash: now refused, plant `irAcceptsClampedRate`;
    - no live-instance reference: the load path is now the reference.
  - **LOW:**
    - the API signature and the renamed plant: ROADMAP T-030 amended;
    - `mulberry`'s ×2 is exact under contraction: commented;
    - this trace.
- **Plants seen firing (`echo_ir_plants`):**
  - irDropsDevice -> I/O gains +6 / -12 dB: differs from the plain render at sample 0 (L 0.089100652418836801 vs 0.044656109500181937)
  - irLevelIgnored -> defaults (synced, loop filter on): differs from the plain render at sample 0 (L 0.8910065241883679 vs 0.089100652418836801)
  - irSkipsOutputFilter -> output filter: differs from the plain render at sample 9600 (L 0.01811317835368818 vs 0.0012843336763763067)
  - irSeedAfterReset -> drift modulation: differs from the plain render at sample 7460 (L -0.0011808737805289226 vs 0)
  - irReusesState -> 'free 250 ms, fb 0, filters off' after another patch differs from a fresh render at sample 0
  - irSeedAfterReset -> 'drift modulation' after another patch differs from a fresh render at sample 7460
  - irAcceptsClampedRate -> a 4000 Hz request was rendered (the engine runs at 8000 Hz)
  - irHashSkipsKey -> changing mod.seed leaves the hash unchanged: a stale drawing would be served
  - noTailGate -> fb 0 %: 5.65e-53 after the declared tail (16808 samples)
  - irRestAtMissesEnd -> a render of 6144 samples, resting in its last block, reports restAt -1
  - irLevelIgnored -> at -20 dBFS the first repeat peaks at 1, want 0.1
  - irAllocsInRender -> 2 allocations in a prepared render
- **Alternatives rejected:**
  - a fresh prepared instance per render: ~18 MiB allocated and cleared each time at 192 kHz, and `reset()` is
    bit-identical to it (contract A2);
  - folding the checks into `core_tests.cpp`: it collides with M3's appends (D-030);
  - drawing the knob-path curve: not a function of the patch (D-031).
