# plan-map — a roadmap visualizer parsed from ROADMAP.md, after the siblings' plan maps

- **Queue item:** unqueued: the human's request, relayed by the Echo lead session (2026-10-20): "Can we
  also get up a roadmap visualizer like your sibling projects and Horde have so I can follow the progress
  and see what's left?"
- **Why:** the human follows progress visually. ROADMAP.md is Echo's single source of truth, so the map
  must not hold a second, hand-edited copy of phase state.
- **What the siblings do (surveyed first):** horde's `docs/design/h2-plan-map.html` (B387) and the plan
  maps of Bulwark (D-081), Sluice and Scape are hand-written single-file pages at
  `docs/design/<name>-plan-map.html`, served from the repo root (Sluice: a `plan-map` entry in
  `.claude/launch.json`). The shape is a node per part with status colour, a side panel per part, a tally
  of what is left, ROADMAP rows read live, and `?check=1` self-checks, each with a must-fail control. None
  is generated, none has a `./verify` gate, and none is published as an Artifact. Their DATA blocks
  hand-type each part's status.
- **Changed:**
  - `docs/design/echo-plan-map.html` (new) is that shape with one deliberate difference: it has **no data
    block**. Every phase, gate, phase state, queue item, open and closed question, deferred item and the
    cutoff date is parsed from ROADMAP.md on load. Phase state comes from a phase's own `**Status:**`
    bullet if one is ever added; otherwise from the clause heads of the Status block's `**Phase:**`
    bullet; otherwise "not started". The rule is in the page's header comment.
    - It shows a progress strip and phase cards with horde's 2026-12-11 cutoff after M3 (the phase whose
      gate says "Due"), what is left before and after the cutoff, the queue, and Q-A3.
    - It flags a gate that is still undefined (M4's), and marks it overdue once the phase it was due at
      has closed.
    - Its four self-checks each have a planted control: it parses cleanly, every phase has a gate and the
      cutoff is found, closed phases come first, and ids are unique.
    - The MODEL section is pure (no DOM, no clock). The UI reads the viewer's clock once, for "days to
      the cutoff", and labels it as the viewer's.
  - `tools/plan_map_smoke.mjs` (new) slices the page's MODEL at its banners and runs it headlessly
    against ROADMAP.md. It checks the self-checks and their controls, that all seven phases are found
    (control: the M2 heading demoted), and that the model is pure. Purity is checked two ways: a static
    scan (control: a planted `Date.now()`) and a run with Date poisoned. It pins no phase state, so it
    stays green as the ROADMAP moves.
  - `.claude/launch.json` (new): a `plan-map` static server on the repo root.
  - `README.md` map and `CODEMAP.md` list both files.
  - ROADMAP.md is NOT edited.
- **Evidence:**
  - `node tools/plan_map_smoke.mjs` is green on three ROADMAPs: main's (8187aef), `close-phase-a`'s
    (524c49d), and the M1 session's working copy. Phase A reads "gate met" on main and "closed" on the
    other two, matching each file's Status line. Every control fired.
  - Served at 127.0.0.1 in the app's browser with `?check=1`: four PASS, four controls fire.
  - Screenshots: desktop at 1400 px in the dark theme (headless Chrome). The light theme was not
    screenshotted.
  - At 375 px (mobile emulation) there is no horizontal scroll and the phases stack into one column.
  - Opened as a plain file, the page shows its "open ROADMAP.md" fallback instead of a wrong picture.
- **Alternatives rejected:**
  - A hand-written DATA block like the siblings': it is a second copy of phase state.
  - A generator script writing a snapshot into the HTML plus a drift gate: that is still a copy, it needs
    regenerating on every ROADMAP edit, and the M1 session edits the ROADMAP in parallel.
  - Adding a `**Status:**` line to every phase in ROADMAP.md: the cleaner input, but it would conflict
    with the M1 session's edits to the same file. The parser accepts that line if the lead adopts it later.
  - Publishing as an Artifact: no sibling does. It would be a snapshot, so it is offered, not done.
